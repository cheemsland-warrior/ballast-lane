The compilation error happens because the AddAutoMapper method overload you are trying to use expects an Action<IMapperConfigurationExpression> callback rather than a Type reflection parameter.

To register your AutoMapper profile using an assembly type scan, you need to use the method signature that takes assembly arrays or parameters, or pass it explicitly inside the configuration action.

Here are the two easiest ways to fix AutoMapperExtensions.cs:

Option 1: Pass the Assembly (Recommended)
You can point AutoMapper to the assembly where MappingProfiles lives, which allows it to scan and automatically register any other profiles you add to that assembly in the future.

C#
using AutoMapper;
using Microsoft.Extensions.DependencyInjection;
using System;

namespace API.Extensions
{
    public static class AutoMapperExtensions
    {
        public static IServiceCollection AddAutoMapperWithValidation(
            this IServiceCollection services,
            bool isDevelopment)
        {
            // Get the assembly containing MappingProfiles and pass it to AutoMapper
            services.AddAutoMapper(typeof(MappingProfiles).Assembly);

            return services;
        }
    }
}

Step 1: Check your AddDatabaseConnectionsExtension method

The error 28P01: password authentication failed for user "postgres" means your application is hitting a PostgreSQL instance on localhost:5432, but the password it's using (Secret) doesn't match what the database expects.

Since your docker-compose.yml explicitly sets the password to Secret, this usually happens because of one of two reasons:

1. An old PostgreSQL volume is conflicting
If you ran this Docker container in the past with a different password, PostgreSQL initialized its data directory with that old password. Changing it in the docker-compose.yml later does not overwrite the master password inside an existing volume.

The Fix: Reset the volume to force PostgreSQL to read your new configuration.

⚠️ Warning: This will wipe any existing local data inside this specific container setup.

PowerShell
# Stop and remove the existing container and its volume
docker-compose down -v

# Start it back up fresh (this will re-initialize the DB with 'Secret')
docker-compose up -d
2. A native PostgreSQL service is running on your machine
If you installed PostgreSQL directly onto Windows using an installer in the past, it runs as a background Windows service on port 5432. Your Docker container is failing to bind to the port, and your migration command is accidentally trying to talk to your native Windows Postgres installation instead of Docker.

The Fix: Stop the native Windows service so Docker can take over the port.

PowerShell
# Stop the local Windows PostgreSQL service
net stop postgresql-x64-15
# Note: If your version isn't 15, press Windows Key, type "Services", 
# find PostgreSQL, and click "Stop".
Once stopped, restart your Docker container using docker-compose up -d so it can cleanly claim port 5432.
